# Internationalization

The kit speaks `vue-i18n` natively. It ships its base messages (**fr** and
**en**) under a dedicated namespace — your own messages live next to them, no
collisions, and can **override** the kit's.

## Install

```ts
import { createForgeI18n } from "@forge/i18n"

const i18n = createForgeI18n({
  locale: "en",            // default: "fr"
  fallbackLocale: "en",    // default: "en"
})

app.use(i18n)
```

## Adding your messages

Pass them to `createForgeI18n` — they are merged **on top** of the kit's (yours
win on conflict):

```ts
const i18n = createForgeI18n({
  locale: "en",
  messages: {
    en: {
      dashboard: { title: "Overview" },
      // Overriding a kit key:
      forge: { actions: { new: "Add" } },
    },
    fr: {
      dashboard: { title: "Vue d'ensemble" },
    },
  },
})
```

In your components, plain `useI18n()`:

```vue
<script setup lang="ts">
import { useI18n } from "vue-i18n"
const { t } = useI18n()
</script>

<template><h1>{{ t("dashboard.title") }}</h1></template>
```

## Switching language live

`locale` is reactive — a selector is enough:

```ts
import { useI18n } from "vue-i18n"

const { locale } = useI18n()
function setLocale(l: string) {
  locale.value = l
  localStorage.setItem("app:locale", l)   // persist wherever you like
}
```

Every kit string (buttons, pagination, confirmations, forms…) switches
instantly.

## Adding a language to the kit

The kit ships fr and en. For another language, provide the kit-namespace keys
in your `messages` (with `fallbackLocale` covering the gaps):

```ts
createForgeI18n({
  locale: "es",
  messages: {
    es: {
      forge: {
        actions: { new: "Nuevo", edit: "Editar", delete: "Eliminar", /* … */ },
        index: { search: "Buscar…", /* … */ },
        // …see ui/i18n/en.ts for the full key list
      },
    },
  },
})
```

## Inside kit components

Internal to the kit (and handy for your custom field components):
`useForgeT()` automatically prefixes the namespace — `t("actions.edit")`
instead of `t("forge.actions.edit")`. The namespace lives in `brand.ts`, never
in templates.

::: tip Resource labels
Resource and field `label`s are declared server-side and arrive as props —
they don't go through vue-i18n. For a back-office that is multilingual at the
data level, declare your defs with the labels of your operators' language.
:::
